# 项目功能大纲：Bilibili RAG（智库云·收藏夹知识库）

> 目标：把你在 B 站收藏的访谈/演讲/课程等内容，自动转成“可检索、可追溯来源、可对话”的个人知识库。

## 1. 项目定位与核心价值

- **一句话**：从 B 站收藏夹拉取视频 → 转写/提取文本 → 向量化入库 → 用 RAG 对话检索。
- **适用人群**：
  - 喜欢收藏学习视频但很难复盘的人
  - 需要把公开视频沉淀成“可查、可问、可引用”的资料库的人
  - 做知识整理/复习/内容回顾/会议分享复盘的人
- **核心卖点**：
  - 自动化流程：同步收藏夹、ASR 转写、向量检索、问答
  - “带来源”的回答：回答可附带相关视频标题与链接
  - 本地存储：SQLite + ChromaDB（向量）持久化

## 2. 功能清单（按用户视角）

### 2.1 登录与会话

- **B 站扫码登录**：获取二维码、轮询确认状态、创建会话。
- **会话查询/退出登录**：会话有效性检查与注销。

相关后端接口（`app/routers/auth.py`）：

- `GET /auth/qrcode`
- `GET /auth/qrcode/poll/{qrcode_key}`
- `GET /auth/session/{session_id}`
- `DELETE /auth/session/{session_id}`

### 2.2 收藏夹管理（同步前的“选源”）

- **拉取收藏夹列表**：展示收藏夹标题、视频数量。
- **展开查看视频列表**：获取收藏夹全部视频（用于用户预览与数量校准）。
- **默认收藏夹快速整理（可选）**：
  - 支持对默认收藏夹进行“整理预览”与“执行移动”（后端已提供接口；前端提供入口按钮与弹窗）。

相关后端接口（`app/routers/favorites.py`）：

- `GET /favorites/list?session_id=...`
- `GET /favorites/{media_id}/videos?session_id=...&page=...`
- `GET /favorites/{media_id}/all-videos?session_id=...`
- `POST /favorites/organize/preview?session_id=...`
- `POST /favorites/organize/execute?session_id=...`
- `POST /favorites/organize/clean-invalid?session_id=...`

### 2.3 知识库构建/更新（入库）

- **查看入库状态**：每个收藏夹显示：未入库 / 已入库 / 有更新、已入库数量与最近同步时间。
- **同步收藏夹**：将收藏夹内容与本地记录对齐（新增/移除/更新候选）。
- **构建向量库**：对新增/需要更新的视频执行内容获取→切分→向量化→写入 Chroma。
- **构建进度**：支持任务状态轮询，展示当前步骤、总体进度、成功/失败信息。
- **知识库维护**：清空全库、删除某个视频的入库内容。

相关后端接口（`app/routers/knowledge.py`）：

- `GET /knowledge/stats`
- `GET /knowledge/folders/status?session_id=...`
- `POST /knowledge/folders/sync?session_id=...`
- `POST /knowledge/build?session_id=...`
- `GET /knowledge/build/status/{task_id}`
- `DELETE /knowledge/clear`
- `DELETE /knowledge/video/{bvid}`

### 2.4 问答与检索（RAG）

- **问答**：输入问题，系统基于已入库内容回答；可返回关联视频来源列表。
- **流式问答**：前端优先调用流式接口，逐字输出；失败时自动回退到非流式。
- **语义检索**：支持直接检索相关片段（用于“找视频/找片段”）。

相关后端接口（`app/routers/chat.py`）：

- `POST /chat/ask`
- `POST /chat/ask/stream`
- `POST /chat/search?query=...&k=...`

## 3. 核心流程（端到端）

### 3.1 首次使用

1. 前端扫码登录（拿到 `session_id` 并保存本地）
2. 拉取收藏夹列表
3. 勾选要入库的收藏夹 → 点击“入库”
4. 后端开始构建任务：
   - 拉取收藏夹内所有视频
   - 对每个视频获取内容（优先 ASR，失败再兜底基础信息）
   - 切分文本 → Embedding → 写入 Chroma
   - 同步状态写入 SQLite
5. 在对话区提问，得到“回答 + 来源视频”

### 3.2 日常增量更新

1. 刷新收藏夹状态
2. 选中已有收藏夹 → 点击“更新”
3. 系统会识别新增/需要更新的视频重新入库并更新向量

## 4. 架构与模块划分（按代码结构）

### 4.1 后端（FastAPI）

入口：`app/main.py`

- **路由层（`app/routers/`）**
  - `auth.py`：B 站扫码登录、会话创建/查询/注销
  - `favorites.py`：收藏夹/视频列表读取；默认收藏夹整理（预览/执行/清理失效）
  - `knowledge.py`：同步/构建/任务状态；入库统计；清库/删视频
  - `chat.py`：问答、检索、流式输出；问题路由（direct/db_list/db_content/vector）

- **服务层（`app/services/`）**
  - `bilibili.py`：封装 B 站相关调用（二维码、收藏夹、视频信息、音频地址与下载等）
  - `wbi.py`：WBI 签名/鉴权相关逻辑（用于部分 B 站接口）
  - `asr.py`：ASR 服务（DashScope），支持 URL 转写与本地文件上传转写
  - `content_fetcher.py`：内容获取与降级策略（优先 ASR；音频 403 时本地下载+转码+上传识别；最终兜底基础信息）
  - `rag.py`：向量库与 RAG 问答（Chroma + Embeddings + LLM），提供检索、入库、问答与统计

- **数据层**
  - `app/database.py`：Async SQLAlchemy 初始化与 session 管理
  - `app/models.py`：Pydantic/ORM 模型（包含会话、收藏夹、视频缓存、构建状态等）
  - 持久化：
    - SQLite：`./data/bilibili_rag.db`（默认）
    - Chroma：`./data/chroma_db/`（默认）

### 4.2 前端（Next.js App Router）

入口页面：`frontend/app/page.tsx`

- **页面结构（用户所见）**
  - 未登录：展示产品介绍、登录按钮、演示流程入口
  - 已登录：主工作台（侧边栏 + 对话区）

- **主要组件（`frontend/components/`）**
  - `LoginModal.tsx`：扫码登录弹窗（二维码展示、轮询确认、回传 `session_id`）
  - `Sidebar.tsx`：左侧栏容器（用户信息、会话、会话列表入口等）
  - `SourcesPanel.tsx`：收藏夹列表、展开视频、入库/更新按钮、构建进度条、快速整理入口
  - `ChatArea.tsx` / `ChatPanel.tsx`：对话与消息渲染、流式问答、来源链接展示
  - `OrganizePreviewModal.tsx`：默认收藏夹整理预览与执行
  - `DemoFlowModal.tsx`：演示流程

- **API 调用封装（`frontend/lib/api.ts`）**
  - 统一的 `request()`
  - `authApi / favoritesApi / knowledgeApi / chatApi` 四大模块
  - `NEXT_PUBLIC_API_URL` 支持前端配置后端地址

## 5. 关键能力说明（实现要点）

### 5.1 内容来源与降级策略

`app/services/content_fetcher.py` 采用“分层兜底”策略：

1. **ASR（优先）**：从音频提取文本
2. **音频不可达兜底**：直链拉取失败（常见 403）时，本地带 Cookie 下载音频 → `ffmpeg` 转码/切分 → 上传到 ASR 识别
3. **基础信息兜底**：至少保证“标题 + 简介”可入库，避免全空

### 5.2 RAG 与回答来源

`app/services/rag.py`：

- 文本切分：`chunk_size=1000, chunk_overlap=200`
- 向量库：Chroma（持久化目录由 `CHROMA_PERSIST_DIRECTORY` 控制）
- Embedding：优先 `DashScopeEmbeddings`，不可用则退到 `OpenAIEmbeddings`
- 回答：检索 top-k 文档块 → 拼接上下文 → LLM 生成回答

`app/routers/chat.py`：

- 有一套问题路由策略：
  - `direct`：闲聊/与收藏无关
  - `db_list`：清单类（只用标题/简介作答）
  - `db_content`：全库总结类
  - `vector`：具体主题问题（走向量检索）

## 6. 配置与部署要点（面向使用者）

### 6.1 必要依赖

- `ffmpeg`：用于音频转码/切分（Windows 需加入 `PATH`）
- Python 依赖：见 `requirements.txt`
- Node 依赖：见 `frontend/package.json`

### 6.2 环境变量（后端）

配置文件：`app/config.py`（读取 `.env`）

- `DASHSCOPE_API_KEY` 或 `OPENAI_API_KEY`：LLM/Embedding/ASR 的 key（代码里复用同一 key 字段）
- `OPENAI_BASE_URL`：可切换 OpenAI 兼容接口地址
- `LLM_MODEL`、`EMBEDDING_MODEL`
- `CHROMA_PERSIST_DIRECTORY`
- `DATABASE_URL`

前端：

- `NEXT_PUBLIC_API_URL`：后端地址（默认 `http://localhost:8000`）

## 7. 约束、风险与常见问题（FAQ 简版）

- **音频直链 403**：属于平台鉴权/过期等问题，系统会自动走“本地下载 + 上传识别”的兜底流程；请确保 `ffmpeg` 可用。
- **费用**：LLM/Embedding/ASR 通常是按量计费（token/时长）。建议先用短视频测试。
- **隐私与合规**：项目定位为个人学习与技术研究，请自行遵守平台协议与法律法规。
