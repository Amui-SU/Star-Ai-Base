# 智库云移动端大版本完善执行方案

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不打断现有可用版本的前提下，把智库云移动端从“功能可跑”推进到“可稳定分发、可持续迭代、体验闭环清晰”的大版本基础。

**Architecture:** 先稳住配置、权限、任务和模块边界，再进入对话历史、学习复盘、分 P 与多向量后端等产品功能。后端保持 FastAPI + SQLite + Chroma 的本地优先架构，前端保持 Next.js 静态导出 + Capacitor Android 的移动端交付方式。

**Tech Stack:** FastAPI, SQLAlchemy async, SQLite, ChromaDB, LangChain, DashScope/OpenAI-compatible LLM, Next.js 16, React 19, TypeScript, Capacitor Android, Vitest, Pytest.

## 1. 当前状态结论

项目已经不是早期原型，主流程具备继续做大版本的基础：

- 后端测试健康：`python -m pytest` 为 205 passed。
- 前端单测健康：`npm test` 为 21 个测试文件、119 个测试通过。
- 前端生产构建健康：`npm run build` 可完成静态导出。
- Windows 启动器健康：`scripts/dev.ps1 doctor` 检测 Python、Node、npm、前后端依赖、ffmpeg、logs 均通过。
- 本地服务健康：后端 `/health` 返回 healthy，前端 `http://127.0.0.1:3000` 返回 200。

当前短板集中在四类：

- 工程交付：环境变量模板、lint 扫描范围、发布文档与 APK 交付说明需要更清楚。
- 权限边界：模型配置、联网搜索配置现在是全局设置，适合本机个人使用，不适合多人共同使用。
- 长任务可靠性：入库任务已有 `IngestionTask` 持久化状态，但执行仍依赖进程内 `BackgroundTasks`，服务重启后没有恢复或重试。
- 可维护性：`ChatPanel.tsx`、`globals.css`、`chat.py`、`knowledge_bases.py`、`knowledge.py` 已经偏大，继续加功能前需要拆分边界。

**决策：**

不再专门区分“本地部署模式”和“线上 Web 模式”。智库云统一作为多用户 Web 应用设计：本地部署只是用户自己运行这套 Web 应用，线上部署只是放到服务器上运行，AI 服务密钥逻辑不分叉。

**目标：**

正式产品路径采用“用户自带 AI 服务密钥”为主。用户登录后添加自己的 DeepSeek、OpenAI、DashScope、Kimi、SiliconFlow、Zhipu、Tavily 等服务密钥，后续聊天、摘要、复盘、联网搜索优先使用当前用户自己的凭证。

同时在模型选择中预留“官方 / 个人”来源切换：`个人` 使用用户自己的 AI 服务密钥；`官方` 使用管理员配置的全局模型 Key，作为未来平台付费通道占位。现阶段不接入支付，不做扣费，官方通道没有全局 Key 时显示未开通。

**配置：**

```env
API_ACCOUNT_MODE=user_required
PLATFORM_API_ENABLED=false
BILLING_ENABLED=false
```

现阶段不启用平台代付费，不做套餐扣费，只预留 `usage_events` 记录调用量。未来收费时再扩展为 `API_ACCOUNT_MODE=hybrid`、`PLATFORM_API_ENABLED=true`、`BILLING_ENABLED=true`。

**后端设计：**

- 新增 `user_api_accounts`，API Key 用 `APP_ENCRYPTION_KEY` 加密保存。

- Resolver 按用户选择解析凭证：`personal` 读取当前用户启用的 LLM 账号；`official` 读取管理员全局模型配置，缺失时返回 `official_api_required`。

**问题：**

`IngestionTask` 已经持久化任务状态，但任务执行依赖进程内 `BackgroundTasks`。服务重启后，`pending/running` 任务不会自动恢复，也不会明确标记为 interrupted。

**建议方案：**

先做轻量恢复，不引入 Redis/Celery：

- 启动时扫描 `ingestion_tasks` 中 `pending/running` 且更新时间过旧的任务。
- 将无法恢复的任务标记为 `failed` 或 `interrupted`，提示用户重新执行。
- 对 URL 导入、本地视频导入、收藏夹构建保留重新发起入口。

**后续增强：**

- 如果未来要做真正断点续跑，再引入独立 worker 或 SQLite-backed queue。

**测试：**

- 构造一个 `running` 且 `updated_at` 很旧的任务，启动恢复函数后状态变为 `failed` 或 `interrupted`。
- 构造一个刚更新的 `running` 任务，恢复函数不处理。
- 确认任务状态接口仍按知识库归属校验。

**验收标准：**

- [x] 服务重启后，界面不会长期卡在“运行中”。
- [x] 用户能看懂任务中断原因，并重新发起。

## 6. P2 产品功能路线

### Route A: 学习复盘体验版

适合春节大版本主卖点。

**核心能力：**

- [x] 对话历史与会话管理（第一版：用户隔离、按知识库筛选、恢复范围与联网搜索上下文）。
- 检索历史。
- 视频学习摘要。
- 知识库总览。
- 一键生成复习卡片。

**为什么优先：**

这条路线最贴合“把收藏夹变成可复盘知识库”的定位，用户能明显感知升级，而不是只感知工程稳定性。

### Route B: 内容能力扩展版

适合做技术声量。

**核心能力：**

- 支持 B 站分 P 视频。
- 支持更多导入来源。
- 支持更多 Embedding 和向量后端。
- 支持开源本地模型。

**风险：**

会明显增加索引结构、任务队列、成本控制和 UI 选择复杂度。建议在 P1 完成后再做。

### Route C: 移动端体验增强版

适合提升日常使用频率。

**核心能力：**

- 移动端首页改成最近知识库和最近对话。
- 快速提问入口。
- 导入任务通知。
- 失败任务重试。
- 连接设置诊断。

**风险：**

需要较多真实设备验证，尤其是 Android 网络、扫码和文件上传。

## 9. 风险清单

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 全局模型配置被普通用户覆盖 | 多用户混用时互相影响 | 已完成 P1 Task 4 管理员权限收口 |
| 正式产品继续依赖全局 API | 线上部署会产生费用归属和滥用风险 | P1 Task 4.5 已改为个人密钥为主，并通过“官方 / 个人”显式切换预留付费通道 |
| 长视频 ASR 或收藏夹入库中断 | 用户以为任务卡死 | P1 Task 5 标记 interrupted 或 failed |
| legacy route 与新 scoped route 互相引用 | 后续开发容易误改旧流程 | P1 Task 6 抽 service |
| ChatPanel 大文件维护压力 | 新功能回归风险高 | P1 Task 7 已拆出流式 hook、消息列表、输入区、弹窗和空状态组件 |
| 移动端出现乱码/问号标题 | 观感不专业 | P1 Task 8 加显示兜底 |
| lint 扫第三方缓存 | CI 无法使用 lint 作为质量门 | P0 Task 2 修 ignore |
| OAuth state 回调复用 | OAuth 回调可能被跨浏览器复用 | 已通过 HttpOnly/SameSite=Lax 临时 nonce cookie 绑定 state，成功登录后清理 |
| OAuth 回调异常裸打印 traceback | 异常堆栈绕过统一日志系统，排障和日志脱敏策略不一致 | Google OAuth 异常分支已改为 `logger.exception`，并加边界测试禁止 router 直接 `traceback.print_exc` |
| OAuth 网络异常回显上游错误 | httpx 异常文本可能包含请求参数或 provider secret，直接写入响应/日志会扩大泄露面 | WeChat/QQ/Google OAuth 网络异常已统一为固定 502 文案，日志只记录 provider 与异常类型 |
| 验证码发送频率绕过 | 多 worker 或进程重启后可能绕过 IP 发送频率限制 | 已改为数据库持久化窗口计数，生产仍建议叠加网关限流 |
| 验证码明文进入日志 | SMTP 未配置或发送异常时日志若包含验证码，会扩大凭据暴露面 | SMTP 未配置日志已去除验证码明文；DEBUG 模式仍仅通过接口响应返回验证码 |
| B 站二维码 pending state 共享 | 多 worker 下生成二维码与轮询命中不同进程会误报过期 | 旧 `/auth/qrcode` 与新 scoped `/source-bindings/bilibili/qrcode` pending state 均已持久化到数据库；`login_sessions` 仅作热缓存 |
| 旧向量删除失败后继续重建 | 向量库锁定或删除失败时可能追加重复向量 | scoped 收藏夹同步已改为删除旧向量成功后才写入新向量；失败时保留 DB 记录并记录 warning |
| 知识库删除时向量清理失败 | 若先删除 DB 记录但留下向量，SQLite id 复用后可能混入孤儿向量 | 删除知识库已改为先成功清理向量才删除 DB；向量清理失败时返回可重试错误并保留知识库 |
| 收藏夹端点异常路径资源泄漏 | 上游 B 站请求或响应组装异常时可能留下未关闭的 HTTP 客户端 | `favorites.py` 5 个端点已改为 `finally` 关闭 BilibiliService，并新增异常路径回归测试 |
| SQLite legacy 迁移入口过大 | 数据库兼容迁移持续堆叠时容易引入顺序和职责混乱 | 已将 `_ensure_sqlite_legacy_columns` 拆成模块级迁移 helpers，入口只负责 SQLite 判定和调用同步迁移流程 |
| Windows BAT 文档与仓库不一致 | 新用户按 README 双击启动器会找不到文件 | 已补齐根目录中文 BAT 包装器，并用 README 一致性测试保护其委托到 `scripts\dev.ps1` |
| ASR 服务测试覆盖不足 | 本地视频导入依赖 ASR，结果解析和模型切换缺少轻量单元测试会增加回归风险 | 已补充 ASR 结果解析、base URL 拼接、Recognition 输入格式选择和临时模型恢复测试 |
