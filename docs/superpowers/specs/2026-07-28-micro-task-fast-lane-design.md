# 微小任务快速通道设计

## 目标

在不降低可验证性的前提下，缩短文案、样式和局部组件修正的交付时间。流程成本应与改动风险匹配，微小任务只保留最小记录、定向验证和一次提交。

## 任务分级

### 微小任务

必须同时满足以下条件：

- 不改变 API、数据库、持久化格式、权限、安全或登录行为。
- 不增加或升级依赖，不跨越前后端边界。
- 最多修改 3 个生产文件，且能够通过一个提交安全回滚。
- 验收结果可以由定向自动化测试、局部静态检查或一次目标页面检查证明。

微小任务不要求独立 spec 或 implementation plan。任务描述、提交正文或一个六行任务记录必须写明问题、根因、改动、不改范围、验收和验证命令。

### 普通任务

涉及新交互、组件拆分、多个状态或 4 至 10 个生产文件时，使用简短设计说明、隔离 worktree、定向测试和受影响视口验证。

### 高风险任务

涉及数据模型、认证、API、迁移、依赖、部署或跨端发布时，继续使用完整设计、实施计划、测试驱动、完整验证和发布检查流程。

任意一项条件不确定时，按更高一级处理。

## 微小任务流程

1. 确认任务满足全部快速通道条件。
2. 检查工作区；工作区干净时可直接修改，存在无关改动时使用隔离 worktree。
3. 行为或边界变化先写一个能失败的定向测试；纯文档、注释或无法合理自动化的视觉数值调整可记录豁免理由。
4. 做最小改动。
5. 使用 `scripts/verify-fast.ps1` 运行 `git diff --check`、指定的测试和指定文件的 ESLint。
6. 只验证受影响的页面、状态和视口。涉及响应式规则时才要求桌面与移动端两个视口。
7. 检查差异并用一个提交完成任务。

## 快速验证脚本

`scripts/verify-fast.ps1` 接受以下可选参数：

- `-FrontendTest`：相对于 `frontend/` 的 Vitest 文件，可重复传入多个值。
- `-LintFile`：相对于 `frontend/` 的 ESLint 目标，可重复传入多个值。
- `-BackendTest`：相对于仓库根目录的 pytest 目标，可重复传入多个值。

脚本始终运行 `git diff --check`，至少需要提供一个定向验证目标，任何一步失败时返回非零状态。它不得运行全量前端测试、全量后端测试或生产构建。

示例：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-fast.ps1 `
  -FrontendTest components/AuthPage.test.tsx `
  -LintFile components/AuthPage.tsx
```

## 完整验证边界

快速验证只用于开发中的微小任务。以下情况仍必须运行 `scripts/verify-before-commit.ps1`：

- 普通或高风险任务。
- 发布、部署或生成 APK 前。
- 修改共享构建配置、依赖、认证、安全或数据边界。
- 定向测试暴露出跨模块影响。

CI 继续执行完整后端测试、前端 lint、前端测试和生产构建，作为合并后的最终保护。

## 验收标准

1. `AGENTS.md` 能让执行者快速判断任务等级，并明确何时允许直接在当前分支工作。
2. 仓库提供可复制的微小任务记录模板。
3. 快速验证脚本只运行明确指定的目标，并正确传播失败状态。
4. 自动化结构测试锁定脚本参数、快速通道规则和完整验证边界。
5. 现有完整提交验证流程保持不变。
