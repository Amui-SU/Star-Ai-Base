# 视频笔记 UI 小项打磨设计

## 背景与范围

最初审查清单中的主体缺陷和优化项已经落地。本轮只完成四个剩余 UI 小项：

1. 区分 AI 真正生成、B 站官方章节和智能降级结果。
2. AI 操作整块覆盖已有内容前要求用户确认。
3. 统一前后端视频时间戳显示格式。
4. 为笔记搜索增加防抖，并避免过期响应覆盖新结果。

本轮不改变笔记持久化结构，不增加通用 AI 编辑器能力，也不扩展搜索语法。

## 结果来源契约

`VideoNoteAiResponse` 增加结构化字段：

```text
result_source: "ai" | "official" | "fallback"
```

后端已有内部状态按以下规则映射：

| 内部状态      | API 来源   | 含义                                 |
| ------------- | ---------- | ------------------------------------ |
| `generated`   | `ai`       | 模型成功生成                         |
| `official`    | `official` | 使用 B 站官方章节等可信结构化资料    |
| `unavailable` | `fallback` | 模型未配置，使用已有资料或规则整理   |
| `failed`      | `fallback` | 模型调用失败，使用已有资料或规则整理 |

现有 `message` 继续作为用户可读说明。前端不得通过解析消息文字推断来源。

## AI 结果状态卡

AI 面板保存最近一次操作的 `result_source` 和 `message`。新请求开始时显示处理中状态，成功后显示明确状态卡：

- `ai`：成功样式，徽标为“AI 生成”。
- `official`：可信资料样式，徽标为“官方章节”。
- `fallback`：暖黄色提示样式，徽标为“智能兜底”，并说明“未使用 AI 模型，结果来自已有资料或规则整理，请核对”。

状态卡只描述最近一次 AI 操作。网络错误继续显示现有失败提示，不伪装成已应用的降级结果。

## 覆盖确认

三个现有操作按钮在发起请求前检查它们将更新的目标块：

- 生成摘要：摘要和关键观点目标块。
- 生成问题：复盘问题目标块。
- 生成时间戳：时间戳提纲目标块。

只有至少一个目标块已存在且包含有效文本或条目时，才显示应用内确认对话框。空块和首次插入不确认。

确认对话框标题为“覆盖现有内容？”，正文列出将被替换的区块名称；主操作为“继续生成并覆盖”，次操作为“取消”。取消时不调用 API、不进入加载态、不改变撤销栈。确认并成功应用后，现有“撤销 AI 编辑”仍可恢复被覆盖内容。

## 时间戳格式

前端编辑器和后端 Markdown 导出统一使用以下规则：

- 小于一小时：`MM:SS`，分钟与秒均至少两位，例如 `03:24`。
- 一小时及以上：`HH:MM:SS`，小时、分钟、秒均至少两位，例如 `01:02:03`。
- 负数和无效输入按 `00:00` 处理。

后端保留现有小时格式；前端提取聚焦时间格式化助手，并使用与后端一致的输入输出用例测试。

## 搜索防抖与竞态保护

笔记搜索的输入值和实际请求词分离：

- 输入框立即反映用户输入。
- 文本停止变化 `300ms` 后更新实际请求词并查询。
- 知识库变化和“搜索正文”开关仍立即查询。
- 防抖等待期间保留当前列表，不闪烁为空列表。
- 每次查询带请求序号或等价的取消标记；只有最新请求可以写入列表、加载态和错误状态。

这能同时减少逐字请求和慢响应覆盖新结果的问题。

## 组件边界

- 后端 schema 和 AI 建议构建逻辑负责输出 `result_source`，路由只转发响应。
- 前端纯助手负责来源到状态卡展示信息的映射、目标块是否含有效内容的判断和时间戳格式化。
- `VideoNoteWorkspace` 负责请求编排、确认门、过期响应保护与状态组合。
- `VideoNoteAiPanel` 只渲染操作按钮、确认对话框入口所需状态和结果卡。
- 搜索防抖保持在视频笔记工作区的列表加载边界内，不引入全局状态。

## 错误与切换行为

- AI 请求期间切换视频时继续丢弃迟到响应，并清空与旧笔记相关的撤销历史。
- 确认框打开期间切换视频时关闭确认框，避免对新笔记执行旧操作。
- 搜索请求失败显示可读错误；旧请求不得覆盖新请求的成功或失败状态。
- 降级结果仍可应用和撤销，但必须通过状态卡明确标识来源。

## 测试策略

实施遵循测试驱动流程，每项先看到失败测试，再写最小实现：

1. 后端覆盖四种内部状态到三种来源值的映射，并覆盖摘要、问题、时间戳端点响应。
2. 前端覆盖三种来源状态卡的标签、说明和样式类。
3. 覆盖非空目标块弹确认、空块不弹、取消不请求、确认后请求并可撤销。
4. 覆盖 `204 -> 03:24`、`3723 -> 01:02:03` 和无效值归零。
5. 使用假计时器证明连续输入只在 `300ms` 后查询一次。
6. 使用可控 Promise 证明旧搜索响应不能覆盖新结果，并证明正文搜索开关立即查询。
7. 定向测试通过后执行仓库规定的完整提交验证。

## 渲染验收

实现完成后验证以下目标流：

1. 视频笔记工作区打开，AI 真结果、官方章节和降级结果分别显示正确状态卡。
2. 非空摘要、问题或时间戳块触发覆盖确认；取消无副作用，确认后可撤销。
3. 编辑器与 Markdown 导出显示相同格式的视频时间戳。
4. 快速输入搜索词只触发防抖后的最终查询，列表不被旧响应回滚。

桌面和移动视口各验证一次状态卡、确认对话框和搜索交互。当前会话未提供 Browser 插件，因此实施阶段使用仓库 Playwright；若仓库没有现成流程，则使用不写入仓库的临时 Playwright 脚本，并在最终报告中说明回退原因。
