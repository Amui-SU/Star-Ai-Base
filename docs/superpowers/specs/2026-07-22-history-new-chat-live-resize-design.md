# 历史记录“开启新对话”实时伸缩设计

## 背景

桌面端历史记录侧栏支持拖动右侧边框调整宽度。侧栏宽度已经在 `mousemove` 期间实时更新，但顶部“开启新对话”按钮使用 `width: min(100%, 220px)`，达到 220px 后不再随侧栏继续变化，造成按钮与面板宽度反馈不同步。

## 目标

- “开启新对话”按钮始终占满历史面板顶部除搜索和收起操作区以外的剩余宽度。
- 拖动侧栏边框时，按钮跟随父容器宽度逐帧伸缩，不等到松开鼠标后才更新。
- 保持搜索、收起、新建对话和历史列表的现有行为不变。
- 保持桌面端和移动端顶部操作区无溢出、遮挡或文字截断。

## 非目标

- 不修改侧栏最小宽度、最大宽度、拖拽事件或本地宽度持久化逻辑。
- 不改变新对话按钮的颜色、圆角、图标或点击行为。
- 不调整历史记录分组、搜索和数据加载逻辑。

## 方案

采用纯 CSS Flex 布局联动，不向组件新增 `sidebarWidth` 属性，也不在 React 中重复计算按钮宽度。

历史面板顶部栏继续使用水平 Flex 布局：

- “开启新对话”按钮改为可增长、可收缩的主项，使用 `flex: 1 1 auto`、`width: auto` 和 `min-width: 0`。
- 搜索和收起按钮所在的 `.sidebar-history-actions` 保持 `flex-shrink: 0`，继续占用固定宽度。
- 顶部栏现有间距继续由 `gap` 控制。

侧栏拖动时，现有状态流会在每次 `mousemove` 更新 `sidebarWidth`，继而更新侧栏元素宽度。Flex 布局在浏览器重排时自动重新分配剩余空间，因此新对话按钮会与拖动实时同步，不引入额外状态、事件监听或动画延迟。

## 响应式行为

移动端没有桌面拖拽边框，但沿用同一 Flex 规则：按钮填满固定操作区之外的空间。按钮允许收缩，右侧操作按钮保持可见；现有文字与图标在当前最小侧栏宽度下完整显示。

## 测试与验证

1. 先更新布局守卫，使其要求新对话按钮采用弹性宽度且不再保留 220px 固定上限；确认测试在生产 CSS 修改前失败。
2. 修改 CSS 后运行历史面板、移动布局和首页交互的定向测试。
3. 运行前端 lint、完整测试和生产构建。
4. Browser 插件在当前会话不可用，因此使用项目现有测试和常规 Playwright 做渲染验证：打开历史记录，拖动侧栏边框，分别记录拖动前、拖动中和拖动后的侧栏与按钮宽度；确认按钮宽度连续变化，右侧操作区未被挤压，并检查控制台与页面错误覆盖层。

## 验收标准

- 在桌面端按住历史侧栏边框移动鼠标时，“开启新对话”按钮宽度随每次移动实时变化。
- 按钮右边缘始终与搜索/收起操作区保持既有间距。
- 搜索和收起按钮在最小、默认和最大侧栏宽度下均可见、可点击。
- 移动端历史面板顶部无横向溢出。
- 相关自动化测试、lint 和生产构建通过。
