# API Key 配置界面重构设计

## 背景

当前前端有两个 API Key 配置入口：

- 模型下拉菜单中的服务商“配置”弹窗，由管理员维护官方模型配置。
- 用户菜单中的“AI 服务密钥”弹窗，由当前用户维护个人模型或搜索服务凭据。

两个入口的职责不同，但目前都存在信息密度和编辑空间问题。官方模型配置弹窗把基础字段、思考模式和 JSON 编辑器纵向挤在一个较窄的滚动区域；个人密钥弹窗同时展示密钥列表和编辑表单，列表操作、状态标记和表单争抢空间。用户通常面对约 8 个模型服务商，模型切换已有专门的下拉菜单，因此密钥管理页不需要承担模型切换职责。

## 目标

- 让密钥列表、基础字段和自定义 JSON 都获得足够且稳定的空间。
- 将“浏览密钥”和“编辑密钥”拆成连续但独立的视图，降低同时出现的信息量。
- 让官方模型配置和个人密钥编辑共享一致的编辑结构与请求配置体验。
- 保留两套入口现有的权限、接口、保存和验证语义。
- 在桌面与移动端保持清晰的操作路径，不出现裁切、重叠、横向溢出或嵌套滚动陷阱。

## 非目标

- 不修改模型下拉菜单的模型切换行为。
- 不合并官方配置与个人密钥的数据源或后端接口。
- 不新增 API Key 明文回显，也不改变现有加密存储规则。
- 不增加搜索、批量操作、导入导出或新的服务商类型。
- 不重构聊天模型运行时、健康检查或凭据解析后端。

## 整体信息架构

### 模型下拉菜单入口

管理员点击某个服务商的“配置”后，直接打开该服务商的独立编辑视图。编辑视图不包含密钥列表，保留当前服务商上下文，并分为“基础配置”和“请求配置”两个标签。

### 用户菜单入口

打开“AI 服务密钥”后默认只显示密钥列表。弹窗内部具有三种明确视图：

- `list`：浏览全部个人密钥。
- `create`：新增一个个人密钥。
- `edit`：编辑选中的个人密钥。

点击“新增密钥”进入 `create`；点击列表项主体进入 `edit`；编辑视图中的“返回密钥列表”回到 `list`，但不关闭弹窗。顶部关闭按钮始终关闭整个弹窗。

## 密钥列表设计

- 桌面端以两列显示账号条目，移动端降为单列。
- 每个条目展示服务商图标、密钥名称、模型或服务名称、可用状态和默认标记。
- 点击条目主体进入编辑视图。
- “设为默认”“验证”“删除”收进条目的操作菜单，避免每行持续展示三个同权按钮。
- 列表头只保留密钥数量、刷新和“新增密钥”；约 8 个服务商不引入搜索。
- 加载、空状态和条目错误继续显示在列表上下文内。

## 编辑器设计

### 共享外壳

两个入口共享编辑器外壳，外壳负责：

- 服务商标题、图标和上下文信息。
- 返回或关闭操作。
- “基础配置 / 请求配置”标签。
- 可滚动内容区和固定底部操作区。
- 当前标签、草稿和错误信息的稳定展示。

外壳不负责接口调用，也不直接理解官方配置或个人密钥的保存载荷。

### 官方模型基础配置

- API Key。
- Base URL。
- 模型名称。

API Key 沿用现有规则：服务商已配置时留空表示保留已保存值；未配置时必须填写。

### 个人密钥基础配置

- 服务商；创建时可选，编辑时不可更改。
- 密钥名称。
- API Key。
- Base URL。
- 模型或服务名称。
- 启用状态；仅编辑已有账号时显示，新建账号沿用后端默认启用行为。
- 默认状态。

编辑已有密钥时 API Key 永不回显，留空表示不覆盖已保存值。

### 请求配置

抽出共享的请求配置编辑器，提供三种模式：

- `off`：关闭，提交空对象。
- `standard`：使用当前服务商标准模板，JSON 只读。
- `custom`：使用可编辑的自定义 JSON。

自定义 JSON 编辑器占满内容宽度，具有稳定高度和独立纵向滚动。提供格式化操作，并在编辑器附近显示格式状态。保存前必须使用现有 `parseThinkingConfig` 校验：内容必须是合法 JSON 且顶层为对象；数组、标量和语法错误均阻止保存。

标签切换只改变可见分区，不清空任何草稿。自定义模式切换到其他模式时保留本次会话中的自定义草稿；切回自定义模式时恢复草稿。

Tavily 属于搜索服务，不使用思考请求配置，因此个人 Tavily 账号不显示“请求配置”标签。

## 模板与数据流

### 官方模型配置

继续由 `useChatModelSettings` 管理表单状态：

1. 服务商信息中的 `thinking_config` 和 `thinking_template` 用于推断当前模式。
2. 编辑器输出 API Key、Base URL、模型、思考模式和可选 JSON 对象。
3. 保存继续调用现有 `/chat/llm/provider-config`。
4. 后端测试请求成功后才持久化；前端随后刷新模型配置与健康状态。

### 个人密钥配置

继续由 `useApiAccountsPanel` 管理账号 CRUD，并增加视图、标签和请求配置草稿状态：

1. 打开弹窗时并行加载 `/api-accounts` 与现有 `/chat/llm/config`。
2. `/chat/llm/config` 仅用于建立 `provider -> thinking_template` 映射，不改变个人密钥的数据源。
3. 编辑账号时使用账号的 `thinking_config` 和对应模板推断 `off / standard / custom`。
4. 创建或更新时将解析后的 `thinking_config` 写入现有 `/api-accounts` 请求载荷。
5. 模板加载失败不阻止账号列表和自定义 JSON 编辑；标准模板选项对缺少模板的服务商禁用。

个人密钥的“验证”仍作用于已保存账号。它保留在列表操作菜单中，不放入编辑草稿底部，避免用户误以为未保存字段已经参与验证。

## 组件边界

计划新增或调整以下前端边界：

- 共享编辑器外壳：只管理布局、标签与操作槽位。
- 共享请求配置编辑器：管理模式选择、JSON 展示、格式化和局部错误呈现。
- `ModelConfigModal`：组合共享编辑器与官方字段，继续使用现有模型配置回调。
- `ApiAccountsPanelView`：根据 `list / create / edit` 渲染列表或编辑器。
- `ApiAccountsList`：渲染可扫描条目和操作菜单。
- `ApiAccountForm`：组合共享编辑器与个人密钥字段。
- `useApiAccountsPanel`：持有视图切换、模板映射、表单和 CRUD 状态。

不创建一个同时处理两套 API 的通用业务表单。共享仅限视觉结构和请求配置行为，避免官方与个人保存规则相互耦合。

## 操作与错误处理

- 保存期间禁用关闭、返回和重复保存，保持当前防重复提交行为。
- 官方配置错误显示在当前编辑分区或底部状态区，测试请求失败后保留全部草稿。
- 个人账号保存错误保留当前视图和草稿；列表加载错误留在列表视图。
- JSON 解析错误显示在 JSON 编辑器附近，并自动保持“请求配置”标签可见。
- 从编辑视图返回列表使用明确按钮；取消操作返回列表，模型配置入口的取消操作关闭弹窗。
- 删除继续使用现有确认流程；不在此次改动中引入新的确认弹窗系统。

## 视觉与响应式规则

- 官方模型配置弹窗桌面宽度扩大到约 `840px`；个人密钥弹窗保持适合两列列表的约 `1040px` 至 `1120px` 宽度。
- 弹窗宽度在进入编辑视图时保持稳定，避免列表和编辑切换造成跳动。
- 桌面基础字段使用两列网格；API Key、Base URL 和 JSON 编辑器可按内容需要跨满整行。
- 移动端列表、字段和底部操作改为单列；返回、关闭和主要保存操作保持可见。
- 弹窗只保留一个主内容滚动区；JSON 编辑器可以独立滚动，但不得产生横向页面滚动。
- 使用既有主题变量、服务商图标和按钮体系；条目卡片圆角不超过 `8px`，不在卡片内嵌套卡片。
- 次要操作使用熟悉的操作菜单；刷新、关闭、返回等工具操作使用紧凑图标并提供可访问名称。

## 测试设计

### 自动化测试

- `ModelConfigModal`：两个标签切换、模式切换、标准模板只读、自定义 JSON 编辑和错误状态。
- `useChatModelSettings` 或现有配置测试：非法 JSON 阻止保存，合法 JSON保持现有请求载荷。
- `ApiAccountsPanel`：默认列表、进入新增、进入编辑、返回列表、API Key 留空不覆盖、请求配置写入 create/update 载荷。
- 个人账号模板加载失败时，列表和自定义 JSON 仍可用。
- Tavily 编辑不显示请求配置标签。
- 列表操作菜单继续覆盖设默认、验证和删除。
- 样式守卫覆盖稳定弹窗宽度、桌面两列、移动端单列、单一主滚动区和 JSON 编辑器尺寸。

### 渲染验证

使用真实浏览器验证以下流程：

- 模型下拉 -> 配置服务商 -> 切换请求配置 -> 编辑自定义 JSON -> 保存错误或成功状态。
- 用户菜单 -> AI 服务密钥 -> 列表 -> 编辑 -> 返回列表。
- 用户菜单 -> AI 服务密钥 -> 新增 -> 填写基础配置与自定义 JSON -> 保存。

桌面与移动端均检查页面身份、非空渲染、框架错误覆盖层、控制台错误、元素裁切、重叠、横向溢出、固定操作区和标签切换后的草稿保持。

## 验收标准

- 打开个人密钥管理时不再同时看到列表和表单。
- 8 个密钥在桌面首屏以清晰两列排列，移动端以单列排列。
- 两个入口的编辑视图均具有“基础配置 / 请求配置”分区。
- 自定义 JSON 编辑器有足够宽度和高度，格式错误会阻止保存并就地提示。
- 官方配置继续执行保存前测试请求；个人账号验证继续针对已保存账号。
- 编辑已有个人账号时，空 API Key 不会覆盖原密钥。
- 两套接口、权限、模型切换和密钥存储行为保持不变。
- 桌面与移动端无裁切、重叠、横向溢出或相关控制台错误。
