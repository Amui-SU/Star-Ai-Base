# 登录页忘记密码功能设计

## 背景与目标

当前登录页支持邮箱密码登录和邮箱验证码注册，但普通用户忘记密码后只能联系管理员获取临时密码。此次增加自助密码重置流程：用户在登录页通过邮箱验证码证明邮箱所有权，设置新密码，然后返回登录页重新登录。

成功标准：

- 登录密码步骤提供清晰的“忘记密码？”入口。
- 用户可以为当前邮箱获取一次性重置验证码并设置新密码。
- 注册验证码与密码重置验证码不能跨流程复用。
- 重置成功后，验证码立即失效，该用户的现有登录会话全部撤销。
- Web 与移动端登录页均可完整使用该流程。

## 范围

本次包含登录页入口、密码重置表单、前端 API 封装、后端接口、独立验证码存储、会话撤销和自动化测试。

本次不包含已登录用户的“修改密码”、管理员重置流程改造、短信验证码、找回或更改账号邮箱、OAuth 账号绑定策略调整。

## 方案选择

采用独立的密码重置验证码表。它与现有注册验证码表物理隔离，使验证码用途不可混用；同时项目启动时使用 SQLAlchemy `create_all`，新增表可以兼容现有数据库，无需修改现有表结构。

未采用的方案：

- 在现有验证码表增加用途字段：模型更统一，但需要为已有数据库增加列并迁移旧数据。
- 直接复用注册验证码：改动较少，但验证码可以跨用途使用，安全边界不清晰。

## 后端设计

### 数据模型

新增密码重置验证码模型，字段包括：邮箱、验证码哈希、失败尝试次数、过期时间和创建时间。验证码只以 SHA-256 哈希形式存储，有效期为 5 分钟，最多允许 5 次错误尝试。

同一邮箱同一时间最多保留一个有效重置验证码。发送频率继续复用现有 IP 级限流规则。

### 接口

`POST /system-auth/password-reset/send-code`

- 请求：`email`。
- 行为：校验邮箱格式和发送频率；账号存在且状态有效时创建并发送重置验证码。
- 防枚举：账号不存在时仍返回与成功场景相同的通用提示。在调试模式下可以返回一次性调试码，但响应形状不暴露账号是否存在；不存在账号的调试码不写入数据库。

`POST /system-auth/password-reset/confirm`

- 请求：`email`、`code`、`new_password`。
- 行为：校验邮箱、密码字节长度、验证码有效期和错误次数；验证通过后更新密码哈希、删除验证码并撤销该用户全部未撤销会话。
- 响应：仅返回重置成功消息，不创建新会话，也不自动登录。

密码更新、验证码消费和会话撤销在同一数据库事务内完成。验证码错误时只增加尝试次数；达到上限后删除验证码。已停用账号不能通过该流程恢复访问。

### 代码边界

路由只负责 DTO、依赖注入和服务委派。密码重置业务逻辑放入独立的认证服务模块；通用的邮箱格式、密码长度、验证码哈希和限流规则复用现有认证验证码服务，不把业务逻辑放回路由。

## 前端设计

认证步骤增加 `forgot-password` 状态。

- 登录步骤：在密码输入框附近显示“忘记密码？”按钮。
- 重置步骤：显示不可误解的当前邮箱、验证码输入与发送按钮、新密码、确认密码、提交按钮和“返回登录”按钮。
- 发送验证码沿用现有 60 秒倒计时和调试码提示。
- 提交前检查验证码、新密码及两次密码是否一致。
- 成功后清空验证码和密码字段，返回登录步骤，并显示“密码已重置，请使用新密码登录”。
- 失败时保留用户已填写的非敏感内容；切换回邮箱步骤或成功后清空密码和验证码。

页面标题在重置步骤显示“重置密码”，副标题显示当前邮箱。视觉、间距、按钮和错误提示沿用现有认证卡片样式，不引入新依赖。

## 错误与安全处理

- 邮箱不存在时，发送接口返回通用提示，避免直接暴露账号存在性。
- 验证码仅存哈希、短时有效、限制尝试次数，并在成功后一次性消费。
- 注册码与重置码使用不同数据表，不能互换。
- 新密码继续遵守 bcrypt 72 字节上限。
- 密码重置后撤销全部会话，要求所有设备重新登录。
- API 错误使用当前请求客户端的统一错误展示，不记录或回显明文密码。

## 测试与验收

后端测试：

- 已存在的有效用户可以获取重置验证码并更新密码。
- 未注册邮箱收到通用响应且不会创建可用重置记录。
- 注册验证码不能用于密码重置，重置验证码不能用于注册。
- 错误码增加尝试次数，超过上限、过期和已消费验证码均被拒绝。
- 超过 bcrypt 长度上限的新密码被拒绝。
- 成功重置后旧密码不能登录，新密码可以登录，原有 Cookie/Bearer 会话均失效。
- 停用账号不能重置后恢复访问。

前端测试：

- 登录步骤显示入口并切换到重置步骤。
- 发送按钮调用重置码专用接口并进入倒计时。
- 空字段和两次密码不一致时不提交。
- 成功后返回登录步骤、显示成功提示并清空敏感字段。
- API 错误可见且允许修正后重试。
- 认证页结构与移动端响应式检查覆盖新增状态。

## 交付与验证

实现使用隔离 worktree 和测试驱动流程。先运行认证相关基线测试，再为每项行为添加失败测试，完成最小实现后运行后端认证测试、前端认证组件测试、Lint、生产构建和仓库完整提交验证。最终以登录页实际渲染检查确认桌面端与移动端流程可用。
