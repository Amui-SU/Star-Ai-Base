# API 账户全屏配置工作台设计

## 背景

当前 API 密钥编辑已经从列表中拆出独立视图，但编辑空间、信息组织和高级配置能力仍不足。用户需要参考成熟供应商配置工具，将编辑入口升级为全屏配置工作台，并让新增设置真实持久化且参与请求，而不是只扩展前端展示。

现有 `UserApiAccount` 只保存服务商、显示名称、加密 API Key、基础地址、单一模型、思考配置和启用状态。新的工作台需要补充协议、认证、模型映射、兜底模型、请求头、请求体覆盖、User-Agent、官网和备注，同时保持现有模型下拉菜单、官方/个人通道选择和聊天入口不变。

## 目标

- 点击新增或编辑 API 账户后进入全屏配置工作台，不再在小型居中弹窗中编辑。
- 将供应商配置组织为清晰分区，并在桌面和移动端提供稳定的编辑空间。
- 支持现有各服务商预设，并以 `OpenAI Compatible` 和 `Anthropic Messages` 两类基础协议承载其衍生差异。
- 支持任意“调用别名 -> 服务商真实模型 ID”映射和默认兜底模型。
- 支持安全的 User-Agent、Header 和 Body 覆盖，并让配置真实参与请求。
- 提供与可视化字段双向同步的 `advanced_config` JSON 编辑器及全屏专注模式。
- 允许使用未保存草稿测试连接，提供可定位且不泄露密钥的错误反馈。
- 兼容现有账户、现有八个通道和原有模型选择流程。

## 非目标

- 不改变模型下拉菜单的结构、服务商切换交互或聊天页面入口。
- 不回传、展示或记录已保存 API Key 的明文。
- 不提供任意脚本、任意请求地址重写或无约束的认证头覆盖能力。
- 不在首期实现配置导入导出、批量编辑或供应商插件市场。
- 不为每个供应商建立一套完全独立的请求实现；特殊差异必须建立在两类基础协议适配器之上。
- 不将 Tavily 等非 LLM 服务强行套入模型映射和聊天协议设置。

## 方案选择

采用“核心字段独立列 + 高级设置版本化 JSON”的混合方案。

核心身份、连接和查询字段保留为数据库列，便于权限控制、校验、查询和兼容现有调用。模型映射、请求覆盖及其他可扩展设置保存在 `advanced_config` 中，避免为每一种可变设置新增表或频繁迁移。

未采用全部关系化字段方案，因为模型映射和请求覆盖会引入多组关联表、接口和排序语义，首期复杂度与收益不匹配。未采用整份账户配置单一 JSON 方案，因为它会弱化认证边界、字段校验、局部更新和历史兼容能力。

## 信息架构

### 入口与页面身份

个人密钥列表继续作为账户管理入口。点击账户或“新增密钥”后进入 `ApiAccountWorkspace` 全屏视图。工作台具有独立页面身份、稳定标题和返回操作；返回账户列表不会关闭整个账户管理入口。

桌面端顶部固定操作栏包含：返回、服务商图标、账户名称、保存状态、测试连接、保存。主体采用左侧分区导航和右侧内容区。分区导航仅定位内容，不承担模式切换或保存语义。

移动端使用全屏纵向布局，各分区可折叠；底部固定“取消 / 测试连接 / 保存”。页面只保留一个主滚动区，JSON 编辑器和键值列表不得导致页面横向溢出。

### 配置分区

1. **基本信息**：服务商、账户名称、备注、官网、启用状态和默认账户状态。
2. **连接配置**：API Key、请求地址、基础协议、认证方式。
3. **模型配置**：模型别名映射和默认兜底模型。
4. **请求配置**：User-Agent、Header 覆盖和 Body 覆盖。
5. **JSON 配置**：完整 `advanced_config` 文档、格式化和专注编辑入口。

Tavily 等非 LLM 服务复用工作台外壳，但只显示适用于自身的基本信息、连接和服务配置；隐藏协议、模型映射及 LLM 请求覆盖。

### 服务商切换

服务商预设提供默认协议、请求地址、认证方式、官网和可用模型建议。服务商只在新建账户时可切换；编辑已有账户时保持现有服务商只读，延续当前账户身份语义。新建时切换服务商只自动填充尚未编辑或为空的值。对已经修改的字段，工作台展示差异并要求用户明确选择“保留当前值”或“恢复服务商预设”，不得静默覆盖草稿。

## 前端组件边界

- `ApiAccountWorkspace`：持有统一草稿、脏状态、分区导航、保存、测试连接和离开保护。
- `ApiAccountWorkspaceHeader`：渲染页面身份、保存状态和桌面操作。
- `ApiAccountSectionNav`：桌面导航与移动端折叠状态。
- `ApiAccountIdentitySection`：基本信息和账户状态。
- `ApiAccountConnectionSection`：密钥、地址、协议和认证方式。
- `ApiAccountModelMappingSection`：别名表格和兜底模型。
- `ApiAccountRequestOverridesSection`：User-Agent、Header 和 Body 覆盖。
- `AdvancedConfigEditor`：内联 JSON 文本、解析状态、格式化和双向同步。
- `AdvancedConfigFocusDialog`：占满视口的专注编辑层，仅管理独立文本草稿与应用/取消。
- `ApiAccountWorkspaceActions`：移动端固定操作栏。

各分区通过统一草稿接口读写，不直接调用保存 API。工作台负责把字段错误映射回分区，业务保存逻辑不放入纯布局组件。

## 数据模型

### 核心字段

在现有 `UserApiAccount` 基础上增加：

- `protocol`：`openai_compatible` 或 `anthropic_messages`；非 LLM 服务可为空。
- `auth_scheme`：供应商预设支持的认证方案标识，例如 bearer 或专用 API Key Header。
- `website_url`：可选官网元数据，不参与请求。
- `notes`：可选备注元数据，不参与请求。
- `advanced_config`：非空 JSON 对象，默认使用版本 1 的空配置。

继续保留现有 `provider`、`display_name`、`api_key_encrypted`、`base_url`、`model`、`thinking_config`、`enabled` 和 `is_default`。首期将现有 `model` 解释为兼容字段：若新版兜底模型未配置，则使用该字段；新版保存时保持两者的一致值，避免旧调用方读取过期模型。

`thinking_config` 暂时保留为独立字段和现有请求语义。它不合并进 `advanced_config`，以免此次工作台扩展同时改变思考模式协议。

`auth_scheme` 只能从系统支持且服务商预设允许的方案中选择。自定义兼容账户也只能选择系统提供的安全认证方案，不能输入任意认证 Header 名称。

### `advanced_config` 版本 1

```json
{
  "version": 1,
  "model_mapping": {
    "agnes": "claude-sonnet-4-5"
  },
  "fallback_model": "claude-sonnet-4-5",
  "user_agent": "",
  "headers": {},
  "body": {}
}
```

- `model_mapping` 是调用别名到真实模型 ID 的对象；键和值均为非空字符串，别名必须唯一。
- `fallback_model` 是服务商真实模型 ID，不要求出现在映射值中，但必须满足模型 ID 格式校验。
- `user_agent` 是可选单行字符串，禁止控制字符和换行。
- `headers` 是字符串到字符串的对象；Header 名称不区分大小写校验。
- `body` 是 JSON 对象，只允许合并非核心请求字段。
- 未知顶层字段允许持久化，以便前向兼容，但不会自动参与网络请求。

JSON 编辑器编辑的是完整 `advanced_config`，不包含 API Key、服务商、基础地址、协议和认证方式等核心字段。这样既提供完整高级配置能力，也不能通过 JSON 绕过核心字段校验或认证保护。

### 迁移与兼容

数据库迁移为新增列提供安全默认值。读取旧账户时，服务层根据 `provider` 推断协议和认证预设，并以现有 `model` 作为 `fallback_model`；不要求启动时批量重写所有历史行。

旧账户首次保存后写入显式协议和版本 1 配置。无法识别的历史服务商不擅自选择协议，工作台要求用户确认后才能保存或测试。API 响应继续只返回“密钥已配置”状态和脱敏提示，不返回密文或明文。

## 服务商与协议适配

### 服务商预设注册表

建立集中式服务商预设注册表，记录：

- 服务商标识、名称和官方图标；
- 基础协议和认证方式；
- 默认基础地址、官网及模型建议；
- 基于基础协议的请求差异钩子；
- 是否为 LLM 服务以及支持的工作台分区。

现有服务商均通过注册表解析。服务商存在原生差异时，使用 OpenAI 或 Anthropic 基础适配器上的受控扩展钩子，不把差异逻辑散落到聊天服务和路由中。

### 运行时解析顺序

聊天调用入口保持不变，内部按以下顺序得到最终请求：

1. 加载账户及服务商预设。
2. 校验 `advanced_config` 版本和结构。
3. 根据调用模型名称查询 `model_mapping`；未命中时使用 `fallback_model`，再兼容回退现有 `model`。
4. 由基础协议适配器生成标准请求。
5. 合并允许的 User-Agent、Header 和 Body 覆盖。
6. 运行服务商差异钩子。
7. 由系统最后写入目标地址、真实模型和认证信息。
8. 发送请求并沿用现有流式或非流式响应处理。

映射未命中且没有任何兜底模型时，在发送网络请求前失败，并指出需要配置的调用别名。

## 请求覆盖安全规则

### Header

用户可以添加普通业务 Header，但不能覆盖以下类别：

- `Authorization` 及各服务商 API Key Header；
- `Host`、`Content-Length`、`Transfer-Encoding`、`Connection`；
- 内部跟踪、代理或转发身份字段；
- 由系统预设标记为受保护的服务商字段。

比较 Header 名称时忽略大小写。User-Agent 使用独立字段配置，也不能通过通用 Header 列表重复定义。认证信息始终由系统在最后阶段注入。

### Body

Body 覆盖只能增加或覆盖协议允许的采样及供应商扩展参数，不能替换：

- `model`；
- `messages`、`input`、`prompt` 或等价核心输入；
- 工具定义、工具调用结果及结构化响应约束；
- `stream` 及系统用于响应处理的控制字段；
- 认证、目标地址或内部跟踪字段。

受保护字段列表由基础协议定义，服务商预设只能扩大保护范围，不能缩小。前端即时提示违规项，后端再次校验并拒绝整个保存或测试请求。

## JSON 双向编辑

可视化分区和 JSON 编辑器共享同一份有效草稿：

- 表单字段改变后，将已识别字段序列化到 JSON，并保留未知字段。
- JSON 文本只有在语法正确、顶层为对象且通过结构校验后，才可“应用”到有效草稿。
- JSON 解析失败时保留原始文本，显示行列位置，不覆盖最后一份有效草稿。
- JSON 中出现受保护或类型错误字段时，定位到对应路径并阻止应用。

专注编辑器打开时复制当前 JSON 文本作为局部草稿。“取消”丢弃专注层内改动并恢复打开前文本；“应用”通过同一解析器写回工作台草稿。应用不等于保存账户。

未知字段在表单编辑、格式化和保存往返中必须保留，但运行时只消费版本 1 明确定义的字段。

## 接口设计

现有账户 CRUD 接口扩展核心字段和 `advanced_config`，保持 API Key 留空表示“不覆盖已保存密钥”的语义。

新增或扩展草稿连接测试接口。请求体使用与创建/更新相同的配置结构，并额外包含可选账户 ID：

- 已有账户且 API Key 留空时，后端使用该账户已保存的加密密钥。
- 新建账户或明确替换密钥时，使用请求中的密钥进行一次测试，不持久化。
- 测试接口执行完整协议、映射和覆盖校验，但不保存任何草稿字段。
- 权限检查与账户更新接口一致，用户不能借测试接口读取或使用其他用户的密钥。

测试结果使用结构化状态，例如 `success`、`authentication_failed`、`endpoint_unreachable`、`timeout`、`model_unavailable` 和 `invalid_configuration`。返回 HTTP 状态、脱敏摘要和关联配置分区，不返回完整上游请求、认证头或密钥。

## 保存、离开与并发

保存采用单个事务，核心字段和 `advanced_config` 要么全部成功，要么全部不写入。保存失败时保留前端草稿。

工作台比较当前有效草稿与最近一次加载或保存成功后的基线。有未保存修改时，返回列表、关闭管理入口或浏览器导航均触发离开确认。测试连接不清除脏状态；保存成功后更新基线。

保存期间禁用重复保存、服务商切换和离开操作。首期沿用现有账户更新时间或接口冲突语义；如果现有接口没有乐观锁，不在本次额外引入版本锁。

## 错误处理

- 字段错误映射到分区和控件；目标分区折叠时自动展开并聚焦首个错误。
- JSON 语法错误显示行列，结构错误显示 JSON 路径。
- 重复别名、无效兜底模型、非法 URL、非法 User-Agent 和受保护覆盖分别显示明确原因。
- 服务商预设加载失败时仍允许查看账户，但禁用测试和保存，避免写入不完整默认值。
- 新版已保存配置无效时阻止正式调用并提示修复，不静默忽略错误配置。
- 上游错误经过分类和脱敏后进入现有聊天错误链路，附带账户、适配器和模型映射阶段，不附带密钥或完整请求体。

## 视觉与响应式规则

- 工作台占满管理容器或视口可用区域，不放入居中卡片式弹窗。
- 顶部操作栏和移动端底部操作栏尺寸固定，加载文字和错误状态不得推动布局。
- 桌面左侧导航保持稳定宽度；右侧内容使用受约束的双列或单列字段网格。
- 配置分区使用无嵌套的页面区块；仅模型映射行、重复 Header 行等项目可使用轻量边界。
- 图标按钮使用现有图标库并提供可访问名称和工具提示。
- 长 URL、模型 ID、Header 名称和 JSON 内容可在自身编辑区滚动或换行，不造成页面横向滚动。
- 移动端所有字段改为单列，折叠标题和固定操作栏不得遮挡内容或软键盘焦点。

## 测试设计

### 后端单元与集成测试

- 新增列默认值、旧账户读取推断和首次保存迁移。
- 核心字段与版本 1 `advanced_config` 的 schema 校验。
- API Key 留空不覆盖、加密存储和所有响应脱敏。
- OpenAI Compatible 与 Anthropic Messages 请求构建。
- 服务商预设及差异钩子不会绕过基础协议保护。
- 模型别名命中、未命中兜底、旧 `model` 兼容和无模型失败。
- Header 大小写保护、User-Agent 校验和 Body 核心字段保护。
- 未知 JSON 字段往返保留但不参与请求。
- 草稿连接测试使用未保存配置、复用已保存密钥、权限隔离和错误分类。
- 保存事务失败时不产生部分更新。

### 前端测试

- 从列表进入新增/编辑工作台并正确返回。
- 桌面分区导航、移动端折叠和固定操作栏。
- 新建账户时切换服务商只填充空值，已修改值需要显式确认；已有账户的服务商只读。
- 表单到 JSON、JSON 到表单、未知字段保留和格式化。
- 专注编辑器应用、取消、错误保留和“应用不保存”语义。
- 模型映射增删、重复别名和兜底模型校验。
- 受保护 Header/Body 字段在前端阻止测试与保存。
- 测试连接使用当前草稿，状态展示不清除未保存标记。
- 保存成功更新基线，保存失败和离开确认保留草稿。
- Tavily 精简分区不渲染 LLM 专属配置。

### 浏览器验证

使用真实桌面和移动端视口验证：

- 账户列表 -> 新增/编辑 -> 分区编辑 -> JSON 专注模式 -> 测试连接 -> 保存 -> 返回列表。
- 长名称、长 URL、长模型 ID、大型 JSON 和上游错误不会造成遮挡、裁切或横向溢出。
- 模型下拉、官方/个人通道样式和现有聊天调用流程无回归。
- 控制台无新增错误，API Key 不出现在网络响应、错误文字、日志或截图快照中。

## 验收标准

- 新增和编辑个人 API 账户均使用全屏工作台，不再依赖小型编辑弹窗。
- 桌面端具有分区导航，移动端具有可折叠分区和固定操作栏。
- 服务商预设覆盖现有各服务商，并明确归属两类基础协议或非 LLM 类型。
- 任意模型别名能够映射到真实模型 ID，未命中时按定义使用兜底模型。
- 自定义 User-Agent、允许的 Header 和 Body 覆盖真实进入请求；受保护字段无法被覆盖。
- 可视化字段与完整 `advanced_config` JSON 双向同步，未知字段不会在往返中丢失。
- JSON 可进入全屏专注编辑，取消不写回，应用只更新工作台草稿。
- 测试连接使用未保存草稿并提供分类、脱敏的结果。
- 旧账户无需人工迁移即可继续使用，首次保存升级为新版配置。
- API Key 在存储、接口、日志、错误和测试中保持现有安全边界。
- 现有八个通道、模型下拉、官方/个人通道选择及聊天入口行为保持不变。
- 前后端自动化测试和桌面、移动端浏览器验证全部通过。
