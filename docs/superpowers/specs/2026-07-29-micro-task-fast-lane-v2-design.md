# 微小任务快速通道第二版设计

## 目标

修复现有快速通道被完整提交流程抵消、多个定向目标无法通过常用
`powershell -File` 调用可靠传入、暂存与新增文件漏验，以及纯文档和纯样式任务
缺少合法验证路径的问题。微小任务应在保持明确风险边界的前提下，只支付与改动
直接相关的验证成本。

本设计是两批优化中的第一批。CI、全局 pre-commit hook 和 worktree 依赖安装策略
属于第二批，不在本次实现中修改。

## 流程边界

符合快速通道条件的任务使用 `scripts/verify-fast.ps1` 代替
`scripts/verify-before-commit.ps1 -Format` 和随后不带参数的完整验证。普通任务、
高风险任务、发布、部署、共享构建配置变更，以及定向验证发现跨模块影响的任务，
继续使用完整验证流程。

微小任务保持一个可独立提交的 changeset，但只有用户或集成流程要求提交时才创建
focused commit。工作区存在无关改动时，只有目标文件与已有改动重叠，或验证过程会
改写共享状态，才必须创建 worktree。

微小任务记录默认只要求 `Change`、`Acceptance` 和 `Verification`。修复缺陷时补充
`Root cause`；容易误扩范围时补充 `Out of scope`。

## 快速验证接口

`verify-fast.ps1` 保留以下数组参数：

- `-BackendTest`
- `-FrontendTest`
- `-LintFile`

脚本增加目标规范化：同一 PowerShell 会话传入的数组继续有效；通过
`powershell -File` 调用时，单个参数值可使用英文逗号分隔多个目标。脚本禁用位置
绑定，未带参数名的额外路径必须立即失败，不能被误绑定到另一类检查。

脚本增加 `-StaticFile`，仅接受 Markdown、纯文本、CSS、SCSS、Less、HTML、JSON、
YAML 文件。该模式用于无需新增自动化测试的纯文档或纯视觉数值调整。它验证目标
文件存在、扩展名在允许列表中，并运行 Git 空白检查；视觉结果仍需按任务记录进行
一次目标页面检查。代码文件不能借此绕过测试或 lint。

空目标校验在启动 Git、Python 或 Node 之前执行。前端命令优先调用
`frontend/node_modules/.bin` 中已经安装的 Vitest 和 ESLint；本地依赖缺失时明确报错，
不通过 `npx` 隐式联网安装。

## Git 差异验证

脚本分别检查：

1. `git diff --check`，覆盖未暂存的已跟踪文件；
2. `git diff --cached --check`，覆盖已暂存文件；
3. `git ls-files --others --exclude-standard` 返回的新增文件。

新增文本文件使用与 Git 空白检查一致的本地检查，至少拒绝行尾空白、空白行作为文件
结尾和未解决的冲突标记。二进制文件跳过内容扫描。任一步失败都返回非零状态。

## 测试策略

现有字符串结构测试保留为轻量边界守卫，并增加真实进程级契约测试。测试在临时 Git
仓库中复制快速脚本，通过 PATH 中的轻量命令替身记录实际参数，不运行真实全量测试。
契约覆盖：

- 单个和逗号分隔的多个后端、前端及 lint 目标；
- 位置参数被拒绝，且不会误启动另一端工具；
- 空目标在任何外部验证命令前失败；
- 后端、前端和 lint 子命令失败码正确传播；
- 未暂存、已暂存和未跟踪文件的空白错误均会失败；
- `-StaticFile` 接受允许的静态文件并拒绝代码文件；
- 快速脚本不会运行全量测试或生产构建。

## 验收标准

1. `powershell -File` 能在一个参数值中可靠传入多个定向目标。
2. 快速脚本不会把额外目标绑定到错误的工具链。
3. 未暂存、已暂存和新增文本文件都受空白检查保护。
4. 纯文档和纯样式任务无需提供无关测试即可完成快速验证。
5. 微小任务不再触发两轮完整验证，其他风险等级的验证边界保持不变。
6. 进程级测试能够复现旧脚本的问题，并在新实现下通过。

## 第二批边界

第二批将单独设计和实施以下内容：批量且锁版本的 pre-commit 格式检查、CI 路径过滤、
Playwright 安装顺序、PR 并发取消，以及 worktree 的离线依赖安装。第一批不修改用户
级 Git 配置、全局 hook、GitHub Actions 或包管理器。
